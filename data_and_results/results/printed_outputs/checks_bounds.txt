== E1  What bounds the SciFlow-Bench score, and why every system is compressed
==============================================================================

Read-back ceiling (gold graphs drawn by our engine, read by the same reader), n=483:
  score 0.611   node F1 0.824   edge F1 0.470
  node recall 0.817   edge recall 0.544
  -> even a perfect graph loses 43% more of its edges than its nodes under this protocol.

The metric weights edges 0.6 and nodes 0.4, so the reachable score is set by the
quantity the protocol recovers worst. Per item, an edge can only match if both of
its endpoints matched, so edge recall is bounded by the share of gold edges with
two matched endpoints -- node recall squared under independence.

  share of items with edge recall <= node recall^2:
    sciflow   ours  n= 4347  share 0.876  rho(nr^2, er) +0.46  node recall 0.263  edge recall 0.048
    sciflow   DOT   n= 1449  share 0.883  rho(nr^2, er) +0.44  node recall 0.239  edge recall 0.045
    flowvqa   ours  n= 2700  share 0.931  rho(nr^2, er) +0.86  node recall 0.779  edge recall 0.464
    flowvqa   DOT   n=  900  share 0.844  rho(nr^2, er) +0.74  node recall 0.695  edge recall 0.359

  implied band: with node recall at 0.22-0.29 the largest edge F1 any system
  can reach on SciFlow-Bench is about 0.084, so 0.6 of the score is spent on a quantity capped near 0.08.

  the ten system means under the benchmark's protocol:
    sdxl         0.0159
    pixart       0.0196
    qwen         0.0792
    graphviz     0.0866
    gemini2.5    0.1011

  all ten span 0.1088; the eight whose figures carry readable text

== E4  Arrow direction is a separate error, and the metric hides it
==============================================================================

Reversed edges: the extractor found the relation and pointed the arrow the wrong
way. strict_edges_reversed is a count per figure (0-3 here) and is never reported.

  corpus/source          model       rev/fig  % of gold edges  figs with >=1  edge F1
  sciflow (papers)       Qwen          0.021            0.16%           1.8%    0.033
  sciflow (papers)       Gemma         0.023            0.20%           2.1%    0.042
  sciflow (papers)       Ministral     0.040            0.22%           2.4%    0.043
  flowvqa code           Qwen          0.047            0.37%           4.7%    0.748
  flowvqa code           Gemma         0.040            0.25%           3.0%    0.750
  flowvqa code           Ministral     0.057            0.45%           4.3%    0.783
  flowvqa instruct       Qwen          0.117            0.52%          10.0%    0.402
  flowvqa instruct       Gemma         0.110            0.48%          10.0%    0.377
  flowvqa instruct       Ministral     0.217            0.96%          16.7%    0.440
  flowvqa wiki           Qwen          0.080            0.31%           7.7%    0.326
  flowvqa wiki           Gemma         0.187            0.66%          16.7%    0.310
  flowvqa wiki           Ministral     0.237            0.94%          20.0%    0.416

  code   0.048 reversed per figure, 0.36% of gold edges, 4.0% of figures
  prose  0.158 reversed per figure, 0.64% of gold edges, 13.5% of figures
  prose / code ratio 1.8x, Mann-Whitney p = 2.5e-14

  On SciFlow-Bench papers 2.1% of figures carry at least one reversed
  edge, against 13.5% on FlowVQA prose, where gold graphs are denser.

  The rate has to be read beside recall, because only a recovered relation can be
  reversed: a system that finds fewer edges reverses fewer. That is exactly the
  point. Under node-and-edge F1 a reversed edge scores like a missing one, so the
  benchmark cannot separate an extractor that misreads direction from one that
  misses the relation, and the two call for different fixes. A direction-insensitive
  edge F1 reported beside the directed one, or the reversal count itself, separates
  them at no cost; both are already computable from any predicted graph.
